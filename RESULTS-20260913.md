# Native VOLE-PSI and actual model-gradient observations

These are reproducible public-data observations on GitHub-hosted Ubuntu 24.04 runners. Each experiment uses two native processes on one host over TLS loopback. The two experiments ran on different runner CPUs. They do not establish production security, cross-machine performance or formal acceptance.

## VOLE-PSI

[Run 34730761984](https://github.com/leemaple/zhibiao001/actions/runs/34730761984), harness commit `227d6a86a3545c57712fc90384d119ffa0c96cdb`, passed all six cases, three invocations each. Each output array exactly matched the expected sorted receiver row indices, including empty and full intersections.

The code builds the maintainer's [native VOLE-PSI](https://github.com/ladnir/volepsi/tree/ed943f5f814591cdf864777c73b7bc9e7526c1a8) at `ed943f5f814591cdf864777c73b7bc9e7526c1a8`, uses the original file-based RsPsi entry, and adds only an application bytes-sent print. The pinned libOTe commit is `d55867114c78272be7142bd67ebdcb346fec8621`; all observed transitive dependency commits and CMake options are in the artifact. QC is enabled with BITPOLYMUL, with real native base OT/VOLE, semi-honest mode and statistical parameter `ssp=40`. This is not a whole-system “40-bit security” certification. Protocol randomness comes from the native system random seed each invocation; the reproducible seed controls only synthetic dataset generation.

Inputs are unique synthetic 128-bit elements, with deterministic shuffles. Set sizes are exchanged and the receiver receives the ordinary intersection. Empty intersection does not mean empty input sets. The native frontend can catch an exception and exit 0: the harness also requires success markers, no exception text, a newly created output and exact row-by-row equality. An invalid-length input probe confirms this caught-error behavior.

Wall time covers process launch through both exits: file read, TLS setup, size exchange, native protocol, sorting and output. Input generation and the approximately 624-second native build are excluded. The 10M/10M application bytes-sent sum was 328,647,322 bytes; maximum single-party RSS across its three runs was 2,460,412 KiB. These are application counters and per-process memory, not packet-capture wire bytes or simultaneous total memory. CPU: Intel Xeon Platinum 8573C, 4 vCPU; available host memory approximately 16 GB.

## Actual gradient aggregation

[Run 34730937041](https://github.com/leemaple/zhibiao001/actions/runs/34730937041), harness commit `5055e715829aca0f4546bd3a5a479d4e0a9c1e00`, passed three exact integer-sum checks over **50,914 coordinates**. The same gradients were aggregated in all three invocations.

The specified PyTorch model has **50 trainable affine layers**: 4→32, then 48 residual 32→32 tanh blocks, then 32→2. Both parties start from the same random weights and each computes one actual local forward/backward pass on its own 32-row public Iris batch. Every layer has nonzero gradient norm. Local backpropagation is plaintext; only the subsequent Q20 gradient-vector addition runs inside MP-SPDZ `semi2k`.

| Measurement | Observed value |
|---|---:|
| Aggregation process wall, median | 0.047789474 s |
| Aggregation process wall, min–max | 0.046364359–0.058977003 s |
| All three observations ≤ configured 1 s threshold | Yes |
| Two local gradient worker processes including imports, concurrent wall | 1.684746599 s |
| Compilation | 0.560551236 s |
| Maximum mean quantization error | 0.000000473963 |

The quantization error above is a dimensionless absolute gradient error, approximately `4.7396242352e-7`, bounded by `2^-21` plus floating-point allowance. The MPC output is a secret-shared encoded sum. Conversion to a mean by dividing by `2 * 2^20` occurs in the post-run public diagnostic. No model update, convergence experiment or encrypted 50-layer inference is performed.

Aggregation wall covers process startup, TLS/PRG setup, private input, share addition and share persistence. It excludes local gradient generation, input-file preparation, installation, compilation and post-run reconstruction. CPU: AMD EPYC 7763, 4 vCPU. Three observations below 1 second do not guarantee other models, machines, networks or worst-case timing. `PASS_CORRECTNESS` alone is not a performance pass; the separate timing flag must be read.

There is no protocol-level reconstruction: each party saves additive sum shares. The public-data diagnostic then combines both shares after both processes have exited and verifies every coordinate. The artifact intentionally includes both shares and both plaintext gradients; it is not a confidential production evidence package.

The VM reports `Data sent = 0 MB` for this linear path. MP-SPDZ's [SemiInput](https://github.com/data61/MP-SPDZ/blob/26a605368e40fed3a7e9cee78c9a3f4390b85eb5/Protocols/SemiInput.hpp) first exchanges PRG seeds; [Online-Thread](https://github.com/data61/MP-SPDZ/blob/26a605368e40fed3a7e9cee78c9a3f4390b85eb5/Processor/Online-Thread.hpp) resets communication counters after initialization. Input shares and their sum can then be formed locally. The zero VM counter does not mean zero physical TLS or initialization traffic.

## Run and inspect

```bash
gh workflow run volepsi.yml --repo leemaple/zhibiao001 --ref codex/practical-gradient-volepsi
gh workflow run gradient-model.yml --repo leemaple/zhibiao001 --ref codex/practical-gradient-volepsi
```

The workflow files specify Linux dependencies and exact commands. They use ordinary Python with assertions enabled; do not set `PYTHONOPTIMIZE` or use `python -O`. Use a fresh checkout or fresh generated output/vendor directories for a new run. VOLE-PSI is compiled from source; MP-SPDZ uses the hash-pinned official v0.4.3 Linux archive, and gradient generation uses PyTorch 2.8.0 CPU.

Download `volepsi-<run>-<attempt>` or `model-gradient-<run>-<attempt>` from the linked runs. Artifacts retain configuration, dataset seeds and hashes, native output files, logs, execution commands/exit codes, environment details and SHA-256 manifests for 30 days. Small PSI input files are retained; large generated inputs can be recreated from the pinned generator/config and checked against their original hashes. Native binary and source/dependency identities are recorded. Original outputs are retained.
